# 渲染模型：脏标记与帧调度

## 第一性能杠杆是"不画"

把每帧画得更快有上限；让不该发生的帧不发生没有上限。所以引擎的每个阶段都先问一句"有我的事吗"，没有就返回。

这套机制由两部分组成：**脏标记位**表达"什么变了"，**帧调度器**决定"什么时候真的画"。

## 脏标记位

八个位，覆盖一帧的全部阶段：

| 位         | 含义                | 谁关心     |
| ---------- | ------------------- | ---------- |
| `Data`     | 数据源变了          | 图层       |
| `Geometry` | 几何需要重建        | 图层       |
| `Upload`   | 需要上传 GPU        | 图层       |
| `Text`     | 字形/标签变了       | 文本（M1） |
| `Axis`     | 轴域或刻度变了      | 轴（M1）   |
| `Viewport` | 绘制缓冲尺寸变了    | renderer   |
| `Style`    | 颜色/线宽等外观变了 | 图层       |
| `Present`  | 后备缓冲可能已失效  | renderer   |

### 传播链只展开一条

```ts
propagateDirty(Dirty.Data); // → Data | Geometry | Upload
```

这条链存在是因为"数据变了"必然蕴含"几何要重建、要重新上传"。把它写成一次传播，而不是在三个地方各检查一次 `Data`，避免了三处判断漂移。

**`Style` 与 `Geometry` 刻意解耦。** 这是刻意的：改一个颜色不应该重写顶点缓冲。相应的代价是修改样式时必须显式 `request(Dirty.Style)`——但这是可测的，而"颜色改动悄悄触发全量重传"是不可测的。

### `Present` 为什么必须存在

浏览器可以在页面隐藏期间丢弃画布的后备缓冲。如果没有这个位，"重新可见时没什么脏的、于是不画"，用户看到的就是一张黑图。

对应的调度器行为：

```ts
// 变为可见时，即使没有任何脏标记也要请求一次重绘
setVisible(true); // → 若 dirty 为空则请求 Dirty.Present
```

## 帧调度器的四个机制

四个机制全部照搬 LCJS 9.0，因为它们都是纯粹的减法——省掉工作，而不是把工作做快。

### 1. rAF 合并

LCJS 把 766 个调用点汇聚到一个 pending 标志上，我们照做：

```ts
for (let i = 0; i < 20; i += 1) scheduler.request(Dirty.Data);
// 只有一个帧会被排期
```

没有这一层时，一次"追加 1000 个采样点"的批量写入会触发 1000 次 rAF 排期尝试。

### 2. 帧率闸门

`maxFps` 默认是 `undefined`，即**跟随刷新率**。不要硬编码 60：工业面板的刷新率各不相同，硬上限会在 120/144 Hz 屏幕上白白丢掉流畅度。

非焦点图表才应该设一个低值（例如 10）。

```ts
renderer.setMaxFps(10); // 非焦点图表
renderer.setMaxFps(undefined); // 回到跟随刷新率
```

#### 闸门必须按"累计时间"计时

这是本模块最容易写错的地方，值得单独说明。看起来自然的写法是记录"上一帧渲染的时刻"，然后比较 `now - lastRenderTime`。它会在**有上限时死锁**：

1. 首帧到达，间隔为 0，小于最小间隔 → 跳过，并且不更新 `lastRenderTime`
2. 次帧到达，间隔仍然是 0 → 再次跳过
3. ……永远如此

正确做法是累计时间差，并且**只在真正渲染时清零**：

```ts
this.#elapsed += dt;
if (this.#minFrameInterval > 0 && this.#elapsed < this.#minFrameInterval) {
  this.#skippedByFpsCap += 1;
  this.#schedule();
  return;
}
const delta = this.#elapsed; // 被推迟的帧看到的是累计值，不是一个 tick
this.#elapsed = 0;
```

测试里有专门标注的回归守卫，因为一旦改回去，症状是"设了上限就完全不渲染"，而根因离症状很远。

### 3. dt 钳制

```ts
const CLAMP_THRESHOLD_MS = 50;
const delta = elapsed > CLAMP_THRESHOLD_MS ? ASSUMED_FRAME_MS : elapsed;
```

从后台标签页切回来时，真实间隔可能是 5000 ms。把这个值交给动画，画面会瞬间跳完五秒钟的演化。超过 50 ms 一律按一个 60 Hz 帧算。

### 4. 可见性闸门

不可见时不渲染，**但保留脏标记**。丢弃脏标记正是"切回来后图表卡死"的成因：那部分工作已经欠着，没人会再来提醒一次。

同时不可见期间也**不累计时间**，否则重新可见的第一帧会收到一个覆盖整个隐藏期的 delta。

## 不变量

两条一旦违反就会产生"卡死的图表"：

1. **脏标记只在真正渲染时才清除。** 被跳过的帧绝不能丢掉它本该做的工作。
2. **帧率闸门按累计时间计时**，不是按上一个个 tick 的时间戳。

两条都有对应的测试断言。
