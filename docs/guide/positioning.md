# 定位与取舍

## 一句话

**垂直场景完整方案**，对标 LightningChart JS 的 `ChartXY`：保留"开箱有轴、有刻度、有标签"的完整度，但把实现成本集中在两个场景上——超大数据量的离线科研绘图，与多图表高频刷新的工业实时监控。

不是通用可视化库，也不是换皮版的通用绘图基元集合。

## 为什么不是 webgl-plot 那种方式

`webgl-plot` v2 证明了"用 WebGL 画折线"这件事的**最小**实现。它的价值在于把问题缩到足够小，但它的默认行为里有几处不适合工业场景：

| 问题         | `webgl-plot` v2 的做法                    | 本项目的做法                                               |
| ------------ | ----------------------------------------- | ---------------------------------------------------------- |
| 自动量程取舍 | `autoScale()` 静默跳过贡献不足 10% 的序列 | 每一次取舍都经 `Diagnostics` 上报，绝不静默                |
| 尖峰保真     | 无显式保证                                | 降级阶梯**不得触碰数据层**：可以掉帧，不能丢点             |
| 坐标轴       | 完全不含                                  | 属于核心范围                                               |
| 资源生命周期 | 无账本                                    | `ResourcePool` 记账，`destroy()` 后 `assertEmpty()` 硬断言 |

最后一条尤其关键：WebGL 资源泄漏在开发机上通常看不出来，等它变成"跑二十分钟后变慢"时，根因已经离症状很远了。

## 为什么也不是照搬 LCJS

LCJS 9.0 的实现里有大量值得抄的东西，也有明确的成本。我们抄机制，不抄负担：

| 机制       | LCJS 9.0                                                                             | 本项目                                                |
| ---------- | ------------------------------------------------------------------------------------ | ----------------------------------------------------- |
| 帧调度     | rAF 合并 + fps 闸门 + dt 钳制 + 可见性闸门                                           | 机制照搬，四个都实现                                  |
| 着色器变体 | 运行时 GLSL 字符串手术：25 个 feature 按固定顺序做插入/删除                          | 模板声明位置 + 槽位声明目标 + `requires` 拓扑排序     |
| WebGL1     | 完整回退：GLSL ES 1.0 机械转译到 3.00、`ANGLE_instanced_arrays`、`OES_texture_float` | 只支持 WebGL2，按扩展逐项探测降级                     |
| 多图表     | 单共享画布 + 每图表离屏 framebuffer + 合成                                           | 一 canvas 一 renderer，多图用 viewport + scissor 分区 |

### 为什么砍掉 WebGL1 回退

LCJS 保留 GL1 是因为它必须覆盖 `features × primitives × GL 版本 × 精度` 的完整矩阵。代价是永久的维护面：每一处着色器逻辑都要在两套语法下成立。

WebGL2 今天已经基本普遍，这笔成本换不回对等收益。替代方案是**按扩展逐项探测、逐项降级**：

```ts
const report = renderer.capabilityReport;
report.degraded; // 是否有缺失
report.missing; // 缺失的特性清单
report.fallbacks; // 每项缺失对应的具体降级说明
```

每个缺失特性都有一条具名的降级路径，而不是笼统的"WebGL1 或 WebGL2"二分。这条报告通过 `Diagnostics` 以 `'info'` 级别上报——**它是关于运行环境的事实，不是调用方的错误**，因此即使在 `'throw'` 模式下也不会中断构造。

### 为什么不做共享画布 + 合成

共享画布换取的是重叠友好的布局与单图导出，代价是每图表一个 framebuffer 加一次全屏合成。

16 图表的工业看板下，这笔开销是实打实的每帧成本，而重叠布局可以用 DOM 层叠加 `scissor` 达到同样效果。所以我们选分区方案。

## 明确的非目标

- **不做 SVG / Canvas2D 回退。** 场景本身就是"数据量大到 2D 画布扛不住"。
- **不做通用图形基元库。** 目标是图表，不是替代 Three.js。
- **不做动画过渡框架。** 平滑插值在实时监控里是噪声源，在科研绘图里是失真源。
- **不在 M0 提供除三角外的几何管线。** 见[里程碑](/roadmap)。
